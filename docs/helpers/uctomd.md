# UctoMD.exe – open an e-Podání XML in the "Moje daně" portal (EPO form pre-fill)

`{tisk}\UctoMD.exe` (18 KB, .NET Framework 4.0 WinExe, assembly `UctoMD` 1.0.0.2,
"Účto - Moje daně", © 2022 Tichý & spol.). It POSTs an EPO XML filing (DPH, KH, SH,
DPPO, …), already generated by Účto, to the Financial Administration's "otevřít formulář"
interface. The interface answers with a one-time URL, and UctoMD opens that URL in the
default browser. There the user sees the filled-in form in the EPO application on
Moje daně, and can check, sign and submit it. Rebex (`Rebex.Http`/`Networking`/`Common` in
`{tisk}`) supplies the HTTP client.
Decompiled source: `work/decompiled/{tisk}_UctoMD/UctoMD/Program.cs`, `Config.cs`.

## How Účto calls it

| | |
|---|---|
| Wrapper | procedure `UctoMD(xml)`, `UCTO2026_RDB/0637_P_UctoMD.txt` |
| Parameter file | report `UctoMD` (`0636_R_UctoMD.txt`), written to `{TISK}\UctoMD.XML` |
| Command line | none |
| Working dir | Účto's; the config is resolved relative to the exe dir (`APP_CONFIG_FILE=UctoMD.xml`) |
| Input | the EPO XML `epp` (see below) |
| URL | `ADRWEB` record `epomd2` (`{GLOB}\ADRWEB.000`): `https://adisspr.mfcr.cz/dpr/epo_podani?otevriFormular=1` |
| Output | the browser opens the returned URL. `{TISK}\UctoMD.txt` is the Rebex log file, but `logLevel=Off` |
| Sync | `ExecWin(EXE,'')`, fire-and-forget; no `WaitFor`, and nothing is read back |
| Exit code | `-1` after an error MessageBox; not used |

```
(xml:string) var r:real; url:string; begin
  TXT.Path:=PROGRAM.Path+'{TISK}\UctoMD.XML'; puttxt(TXT,'');
  r:=recno(ADRWEB,'epomd2'); if r<=0 then exit; url:=Trail(ADRWEB[r].Adr);
  PARAM3.TTT:=xml+'\13'+url+'\13'+PROGRAM.Path+'{TISK}\UctoMD.txt';
  report(,UctoMD,assign=TXT);
  EXE.Path:=PROGRAM.Path+'{TISK}\UctoMD.EXE';
  if filesize(EXE)=-1 then begin proc(Hlaseni,('Program '+EXE.Path+' pro MojeDaně nenalezen')); exit end;
  proc(ExecWin,(EXE.Path,''));
end;
```

### Call site

`EpoFu(Nov, ZkrEpo, NázEpo)` (`UCTO2026_RDB/0614_P_EpoFu.txt`) is the common
"e-Podání for the tax office" menu used by every FÚ filing (DPH přiznání, kontrolní
hlášení, souhrnné hlášení, daň z příjmů, silniční daň, obecná písemnost, …):

1. `OprXml` fixes the XML in `SEST`. The file goes to `epp` (`{MAIL}\<ZkrEpo>.XML`, or a
   user path with `PARAM3.EpoXmlPath`). It is **CP1250** (`copyfile … mode='LW'`), or
   UTF-8 when `PARAM3.ePoUtf8` is set (converted by `TOUTF8.EXE`).
2. The path goes to the clipboard, then the message "… soubor pro e-Podání: <path>".
3. The menu item `ZkrEpo` → **"e-Podání na internetu »"** opens the submenu:
   * **"Načíst soubor automaticky"** → `proc(UctoMD,(epp))`: this helper.
   * "Načíst soubor ručně (CtrlV)" → `AdrWeb('epomoda')`: opens
     `https://adisspr.mfcr.cz/pmd/epo/formulare?nacteni=1` in the browser, where the user
     pastes the path into the upload dialog.

   Other items in the same menu: Datová schránka, Poslat XML e-mailem, Opravit XML,
   Obsah XML souboru.

## What it does (decompiled C#)

1. `Config`: reads `serviceUrl`, `xmlFileName`, `logFileName` (default `uctomd.txt`; it
   creates the directory), `logLevel` (Rebex `LogLevel` name, invalid → Debug) and
   `encoding` (int, default 65001). An HTTP charset label is derived from the code page:
   1250 → `windows-1250`, anything else → `utf-8`.
2. `GetXmlContent`: fails with "Soubor … nebyl nalezen." if the file is missing. Reads the
   file with `StreamReader(path, CP1250)`. A UTF-8 BOM would switch the reader to UTF-8,
   because .NET detects BOMs by default. Without a BOM, a UTF-8 file is misread as CP1250
   (inferred).
3. Rebex `HttpRequestCreator`, TLS 1.2 only, **`SslAcceptAllCertificates = true`**
   (always), and a `FileLogWriter(logFileName, logLevel)`.
4. `POST serviceUrl`. The header is `Content-Type: text/xml; encoding='windows-1250'`, a
   non-standard parameter that is sent verbatim. The body is the XML text re-encoded to
   CP1250 bytes (the declaration inside is not touched).
5. On HTTP 200, it reads the response and parses it as XML with `SelectSingleNode("/URL")`,
   so the document element must be `<URL>`, whose text is the URL. A non-200 status gives
   `null`, which leads to the MessageBox "Služba nevrátila žádný výsledek. Aplikace bude
   ukončena." (information icon); the code then still tries to parse the response and
   throws.
6. `Process.Start(url)`: the default browser opens the EPO form, pre-filled, on
   adisspr.mfcr.cz. The user continues there (login is not needed for the EPO form;
   submission goes by signature, the data box or the paper confirmation).
7. Any exception → MessageBox "V aplikaci došlo k chybě:\n<msg>" titled "UctoMD [1.0.0.2]",
   then exit code −1.

The expected response shape is `<URL>https://adisspr.mfcr.cz/dpr/epo_formular?…</URL>`,
based on the code. It has not been observed live, because we did not post real data to
the ministry. The exact URL form is irrelevant, since it is only opened.

## Replacement design (Node/TypeScript)

Module `src/engine/helpers/uctomd.ts`, key `uctomd.exe`, in-process. It does not have to
block Účto, but running it synchronously is simpler and it is quick.

* **Config**: read `{TISK}/UctoMD.XML` with the shared `appSettings` reader (CP852 decode;
  the values are ASCII). Map `xmlFileName` through `ctx.mapPath`.
* **Body**: send the **file bytes as they are** and name the encoding from the XML
  declaration (`encoding="windows-1250"` or `"utf-8"`), falling back to a BOM check.
  Header: `Content-Type: text/xml; charset=windows-1250|utf-8`. This gives the same bytes
  as the original for CP1250 files, and it fixes the UTF-8 mis-read (`ePoUtf8`).
  * Keep the original's odd `encoding='…'` parameter only if the server turns out to
    require it. Test it once against the live endpoint with a dummy filing (see below).
* **HTTP**: `fetch` (undici), TLS verification **on**. The original's accept-all is a
  workaround for old Windows root stores, and Node ships current Mozilla roots. Timeout
  30 s.
* **Response**: `fast-xml-parser`, take the root `URL` text, trim it, and accept only
  `https:` URLs. Then `ctx.host.openUrl(url)` (Electron `shell.openExternal`).
* **Errors**: `ctx.ui.message('UctoMD', …)` with the original texts ("Soubor … nebyl
  nalezen.", "Služba nevrátila žádný výsledek.", "V aplikaci došlo k chybě: …"). Also
  offer the fallback "Načíst soubor ručně": open `epomoda` and copy the path to the
  clipboard (`ctx.host.clipboardWrite`).
* Logging: request and response status go to the engine debug log. `logFileName` is
  ignored (`logLevel=Off` anyway).

Still worth replacing: **yes, high priority, small effort.** It is the one-keystroke path
for all tax filings. Without it, the user has to upload the file by hand, which the
Electron app makes harder: the path in the clipboard is a DOS path, so the replacement for
the manual path must copy the *host* path instead.

## Test approach

* **Unit**: config parsing, and charset detection (a CP1250 declaration, UTF-8 with and
  without BOM). Assert the exact request (URL, Content-Type, body bytes) against a mocked
  `fetch`.
* **Response handling**: `<URL>https://…</URL>` → `openUrl` called; HTTP 500 and non-XML
  → message; `<URL>javascript:…</URL>` → rejected.
* **Fixtures**: EPO XML files produced by the engine for the sample company in `{prik}`
  (e.g. DPH přiznání `DPHDP3`, kontrolní hlášení `DPHKH1`) through `EpoFu`.
* **Live (manual, env-gated `MFCR_LIVE=1`)**: post a DPHDP3 for a dummy DIČ and verify
  that the response is `<URL>` and opens a pre-filled form. Record the response shape in
  this document.
* **Engine integration**: any DPH e-Podání menu → "e-Podání na internetu" → "Načíst
  soubor automaticky", with mocked HTTP, then assert that `openUrl` was called.
