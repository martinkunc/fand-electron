# UctoDS.exe – send a file to an ISDS data box (older 2022 version)

`{ap02}\UctoDS.exe` (186 KB, .NET Framework 4.x WinForms, assembly `UctoDS`, namespace
`UctoDSWin`, dated 2022-04). It is the predecessor of `UctoDS2.exe` and does the same
job: log in to ISDS, send one data message with one attachment, and append a line to
`{AP02}\UCTODS.LOG`. Decompiled source: `work/decompiled/{ap02}_UctoDS/`.
Read [uctods2.md](uctods2.md) first; this page lists only the differences.

## How Účto calls it

Same wrapper as UctoDS2: procedure `EpoDS` (`UCTO2026_RDB/0613_P_EpoDS.txt`), menu
**"DATOVÁ SCHRÁNKA" → "-"- starší verze UctoDS 2022"**. It is kept as a fallback in
case the new version fails.

```
TXT.Path:=PROGRAM.Path+'{AP02}\UCTODS.XML';
PARAM3.AAA:=PROGRAM.Path+'{AP02}\'+'\13'+ Trail(FIRMA.Volume)+' '+PARAM2.Nazev;
if nodiakr(PARAM2.pwdDS32)<>PARAM2.pwdDS32 then begin report(,EpoDS,assign=SEST); proc(Utf8,(SEST.Path,TXT.Path)) end
else report(,EpoDS,assign=TXT);
FILE.Path:=PROGRAM.Path+'{AP02}\UCTODS.EXE';
proc(ExecWin,(FILE.Path,''));
```

| | |
|---|---|
| Parameter file | report `EpoDS` (`UCTO2026_RDB/0611_R_EpoDS.txt`) → `{AP02}\UCTODS.XML`; the program looks for `UctoDS.xml` in its directory (case-insensitive lookup needed) |
| Command line | none |
| Output | appends to `{AP02}\UCTODS.LOG` (same format as UctoDS2); logs `DS_ERR.LOG`, `DS_RBX.LOG` |
| Side effect | deletes `UctoDS.xml` in the exe directory after loading |
| Exit code | not used |

Config keys that differ from `UCTODS2.XML`:

| Key | UctoDS (`EpoDS`) | UctoDS2 (`EpoDS2`) |
|---|---|---|
| MIME type | `MimeType` = `EndTxt('.',DS3file)`, i.e. the **extension text** such as `XML` or `PDF`, sent as `dmMimeType` unchanged | computed from the extension (`text/xml`, …) |
| File description | `FileDescription` = `EndTxt('\',DS3file)` (file name) → `dmFileDescr` | file name taken from `Filename` |
| Logs | `errorLog`, `rebexLogFile` (default `ucto-ds-rebex-log.txt`; error log default `UctoDslog.txt`) | `AppLogFile`, `ErrorLogFile`, `RebexLogFile` |
| Flags | `useRebexOnly`, `acceptAllCertificates`, `useRebexVerboseLog` (lower-case first letter) | `UseRebexOnly`, `AcceptAllCertificates`, `UseRebexVerboseLog` |

All other keys (`RecipientDSID`, `SenderDSLogin`, `SenderDSPassword`, `SenderName`,
`RecipientName`, `SenderDSMobKey`, `Subject`, `Filename`, `DSType`, `OutputFilename`,
`OutputFormat=csv`, `OutputEncoding=0`, `Note`) and their FAND sources are identical.
The same encoding caveat applies: the file is declared UTF-8 but is CP852 unless the
password has diacritics.

## What it does (decompiled C#)

* `Program.Main`: `RebexChecker`, config file present check ("Soubor se vstupními
  parametry nebyl nalezen."). Windows XP/2003/Vista/2008 always use Rebex TLS 1.2, and
  the mobile key is refused ("…vyžadována verze Windows 7 a vyšší"). Windows 7+ uses
  Rebex only when `useRebexOnly` is set and no mobile key is used; otherwise native TLS 1.2
  with a .NET version check ("Vaše verze Windows nepodporuje TLS 1.2…").
* `frmMain` ("Účto - modul datové schránky (verze - x)"): read-only fields DS příjemce,
  Odesílatel, Předmět, Soubor; a "--- Testovací větev ---" label; buttons
  **O D E S L A T** and **K O N E C**; a multi-line "Průběh odeslání" text box. For the
  mobile key, a panel "Čekám na potvrzení žádosti o autentizaci na Vašem mobilním
  telefonu." with Storno.
* `ISDSBox`: the same URL scheme as UctoDS2, but without VoDZ and with SOAP 1.1 (the
  default of `SoapHttpClientProtocol`), UserAgent `Danova evidence - Ucto`, MEP
  `applicationName=UctoDS`. Sequence: `GetPasswordInfo`, `GetUserInfoFromLogin`,
  `CreateMessage` (envelope identical to UctoDS2, `dmRecipientOrgUnitNum=-1`), and on
  status `0…` `GetOwnerInfoFromLogin` plus the log line.
  Messages: "Vytvářím datovou zprávu ...", "Status: <dmStatusMessage>",
  "Zpráva odeslána. ID zprávy: <dmID>", then "Program ukončete stisknutím tlačítka K O N E C".
* `ConfirmationServices.SaveToCsv`: exactly the same line format as UctoDS2.

## Replacement design (Node/TypeScript)

No separate implementation. Register `uctods.exe` as an alias of the UctoDS2
replacement (`src/engine/helpers/uctods.ts`) with a key map for the differing config
names. Always use a proper MIME type derived from the extension; the original's `XML`
value is a quirk, not a contract.

The alias still makes sense, because the menu item exists and users (or the hotline)
will pick it when the main item fails. Both entries lead to the same code, so this
fallback no longer adds value. The menu text cannot be changed without touching
the chapters, and that is not needed.

## Test approach

* Config parsing test with a `UCTODS.XML` fixture generated by report `EpoDS`, checking
  the key-name mapping (`errorLog`, `useRebexOnly`, …) and that `MimeType=XML` becomes
  `text/xml`.
* Everything else is covered by the UctoDS2 tests. Add one EngineDriver test that picks
  "-"- starší verze UctoDS 2022" and asserts that the shared helper runs with the
  UctoDS key set.
